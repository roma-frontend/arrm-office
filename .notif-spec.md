# Notification i18n migration spec

Replace every `ctx.db.insert('notifications', {...})` with the `notify()` helper
from `convex/lib/notify.ts` so notification text renders in the reader's language.

## Import

Add (adjust depth to the file's location):
import { notify } from './lib/notify'; // files directly in convex/
import { notify } from '../lib/notify'; // files in convex/<subdir>/

## Mapping

    await ctx.db.insert('notifications', {
      organizationId, userId, type,
      title: '📦 Equipment Assigned',
      message: `You have been assigned "${name}" by ${who}.`,
      isRead: false,
      relatedId, route, createdAt: now,
    });

becomes

    await notify(ctx, {
      organizationId, userId, type,
      titleKey: 'notifications.titles.equipmentAssigned',
      messageKey: 'notifications.messages.equipmentAssigned',
      params: { assetName: name, assignerName: who },
      fallbackTitle: '📦 Equipment Assigned',
      fallbackMessage: `You have been assigned "${name}" by ${who}.`,
      relatedId, route, createdAt: now,
    });

Rules:

- DROP `isRead: false` — notify() sets it.
- DROP `createdAt: Date.now()` — notify() defaults to it. KEEP `createdAt: now`
  (or any shared/other variable) so batches stay aligned.
- `fallbackTitle`/`fallbackMessage` = the EXACT English strings that were there
  before (keep the emoji). For sites whose text was Russian, write the natural
  English equivalent — never leave Russian in a fallback.
- `params` values must be RAW (names, dates, numbers, ids) — never a
  pre-formatted or pre-translated sentence, and never a pre-joined English
  phrase. Param names must match the `{{placeholders}}` in the key exactly.
- To pass an enum through, send the raw enum value; the locale string nests the
  label itself via `$t(...)`. e.g. `params: { type: leave.type }` against
  `"... $t(leaveTypes.{{type}}) ..."`. Do NOT map it to English yourself.
- If the existing `metadata` held extra data (ids, flags), pass it as `extra:
{ ... }` — notify() merges it beside the i18n keys. Do not hand-write
  `metadata`.
- Where the old code branched between two strings (ternary on status/approved),
  branch on `titleKey`/`messageKey` instead and keep both keys.
- Where a message had an optional trailing clause (`${c ? ` Note: ${c}` : ''}`),
  pick between the two provided keys (…WithNote / plain) and only include the
  extra param when set: `...(c ? { comment: c } : {})`.
- Preserve surrounding logic exactly: loops, guards, `continue`, the variable
  the id is assigned to (`const notificationId = await notify(...)` still works,
  notify returns the new id), and any `ctx.scheduler` call that uses it.
- Do NOT touch `ctx.db.insert('auditLogs', ...)` or any other table.

## Keys

The full list of available keys is in `.notif-keys.txt` at the repo root, as
`key = "English text"` with the `{{params}}` each one expects. Read it first.
Every string you need is already there — pick the key whose English text matches
the old string. If you are certain none fits, say so in your final report rather
than inventing a key (a key that doesn't exist renders as raw text).

## Reference

`convex/leaves/mutations.ts` is already fully migrated — read it for the house
style, including the ternary-key and optional-param patterns.
